Uma visão geral do Gerenciador de Colação de Grau e Diplomas.

O Gerenciador de Colação de Grau e Diplomas acompanha o aluno da conferência dos dados pessoais até o encaminhamento do diploma.

No topo aparecem o seu nome e, logo abaixo, a sua descrição na lista de acesso. Em Aparência você escolhe Sistema, Claro ou Escuro; a escolha fica guardada só neste navegador. O que você pode fazer depende do seu perfil: veja .

Como o aluno avança

1. Dados Pessoais → 2. Histórico Escolar → 3. Colação de Grau → 4. Emissão de Diploma
  • A etapa atual do aluno é calculada pelo próprio sistema — não é escolhida livremente por quem está usando a tela.

Quem pode abrir o gerenciador e o que cada perfil pode fazer.

Só abre o gerenciador quem está na lista de acesso mantida pelo Serviço de Graduação. A conferência é feita pela conta institucional com que você entrou no navegador.

Etapa 1 — Dados pessoais

Campos

  • Nome completo, Nº USP, e-mail, Nº RG — identificação do aluno.
  • Gênero (concordância) — usado apenas para a concordância gramatical (por exemplo, "aluno"/"aluna", "formado"/"formada") nos textos dos documentos gerados pelo sistema (certificado, ofício, e-mails). Não tem outra finalidade no sistema.
  • Habilitação(ões) — Formação de Psicólogo(a), Bacharelado e/ou Licenciatura, cada uma com seu próprio campo de ano de conclusão. Marcar aqui é o que faz o aluno passar a ser acompanhado nessa(s) habilitação(ões) pelo resto do fluxo.

Salvar x Confirmar

  • 💾 Salvar Alterações — grava os campos sem mudar de etapa.
  • ✅ Confirmar Dados Pessoais — salva e avança para a etapa Histórico Escolar numa única operação.
Depois de confirmados, os dados pessoais ficam bloqueados para edição direta. Para corrigir algo depois disso, é preciso .

Histórico escolar — qual arquivo usar

Isto precisa ficar muito claro: o arquivo certo importa tanto quanto os dados nele.

Para a análise automática, o documento correto é o "Histórico Escolar Completo USP" da habilitação correspondente:
Histórico Escolar Completo USP (Psicólogo) · Histórico Escolar Completo USP (Bacharelado) · Histórico Escolar Completo USP (Licenciatura)
Não confundir com o "Histórico Escolar Final USP". O Final pode existir como documento administrativo, mas é um documento distinto — o analisador precisa do Completo, porque só nele estão as informações detalhadas (disciplinas, créditos) necessárias para a avaliação.

Outros cuidados

  • O PDF precisa ter texto real — um histórico escaneado como imagem pode não ser interpretado pelo leitor.
  • Se nenhum arquivo compatível for encontrado, o sistema avisa; ele nunca adivinha qual arquivo usar.
  • Se mais de um candidato for encontrado, o sistema também não adivinha — é preciso resolver a duplicidade (ver ).

Análise automática de histórico escolar

Em linguagem simples, o que acontece ao clicar em "Analisar Histórico Escolar (automático)":

  1. O sistema localiza o PDF correto na pasta do aluno.
  2. O texto do PDF é lido no próprio navegador.
  3. Os dados relevantes são extraídos.
  4. O servidor identifica o currículo do aluno.
  5. As Regras Curriculares correspondentes a esse currículo são carregadas.
  6. O motor de regras verifica cada habilitação separadamente.
  7. O resultado fica registrado permanentemente na auditoria.
A análise automática é um apoio. Ela NÃO marca sozinha que uma habilitação cumpre os requisitos — quem marca isso é sempre a pessoa responsável, na tabela de Habilitações do . A decisão final é sempre humana.

O que significam os resultados

APTO — todos os requisitos avaliados para aquela habilitação foram cumpridos.

NÃO APTO — existe pelo menos um requisito objetivamente não cumprido.

CONFERIR — o sistema não tem segurança suficiente para concluir sozinho. Alguns exemplos: dado não reconhecido, arquivo não localizado ou ambíguo, ruleset não disponível para aquele currículo, regra em revisão/instável, ou informação necessária ausente no histórico.

A filosofia por trás disso é simples: "na dúvida, o sistema não decide." CONFERIR nunca deve ser tratado como sinônimo de reprovação — é um pedido de conferência humana.

Psicólogo + Bacharelado

Quando aplicável, o mesmo PDF anexado para Formação de Psicólogo(a) pode ser aproveitado para avaliar também o Bacharelado:

  • O arquivo é lido uma única vez;
  • Mas os dois conjuntos de regras curriculares são avaliados separadamente;
  • Por isso um mesmo aluno pode receber, por exemplo, Psicólogo = Não Apto e Bacharelado = Apto — ou qualquer outra combinação. Isso não é um erro.
As contagens de um lote são feitas por habilitação, não por aluno. Exemplo: 3 alunos com Psicólogo + Bacharelado podem gerar até 6 resultados de habilitação. É por isso que a soma dos resultados pode não bater com o número de alunos selecionados — ver .

Análises registradas

"📄 Ver Última Análise" e "🕘 Ver Histórico de Análises", disponíveis no Modal do Aluno, não leem o PDF de novo — eles apenas consultam o que já foi registrado na auditoria permanente de análises.

  • Cada execução da análise automática cria uma nova sessão registrada.
  • Sessões (análises) anteriores nunca são apagadas.
  • Esse histórico continua acessível mesmo depois de o aluno avançar de etapa.
Se "Ver Última Análise" disser que não existe análise, é porque ainda não foi executada e registrada nenhuma análise automática para esse aluno — veja .

Relatórios de histórico escolar

Relatório individual

  • Um PDF por aluno/sessão de análise — pode reunir mais de uma habilitação;
  • Detalhado;
  • Salvo automaticamente na pasta do próprio aluno;
  • Possui versionamento.

Ao gerar novamente, é preciso escolher:

OpçãoO que acontece (exemplo com v1, v2, v3)
Substituir a última versãoContinua v1, v2, v3 — mas v3 é atualizado
Criar nova versãoPassa a existir v1, v2, v3, v4

A análise em si (a sessão registrada) nunca é apagada, mesmo quando o PDF do relatório é substituído.

Relatório consolidado

  • Resumo administrativo cobrindo vários alunos de uma vez;
  • Resultados organizados por habilitação;
  • Mostra as principais pendências;
  • Efêmero — abre em uma nova aba e não é salvo automaticamente; para guardar, é preciso salvar/imprimir manualmente.

Análise de histórico em lote

Roda a análise automática aluno por aluno, em sequência. Uma falha em um aluno não apaga nem prejudica o resultado dos demais. As contagens finais são por habilitação — veja .

Ao final, dois botões ficam disponíveis:

  • Salvar relatórios individuais nas pastas dos alunos — cria um PDF individual para cada aluno elegível e salva na respectiva pasta, tratando o versionamento normalmente.
  • Abrir relatório consolidado do lote — gera um único PDF resumido cobrindo todos os alunos do lote, que abre em nova aba e não é salvo automaticamente.

Proteção contra duplicidade

  • O sistema registra quando um e-mail já foi enviado;
  • Um novo envio para o mesmo aluno exige confirmação;
  • Existe a opção "🔓 Desmarcar e-mail enviado (permitir reenvio)" quando o reenvio for realmente necessário;
  • No envio em lote, o sistema confere a cota disponível antes de disparar;
  • Os destinatários de um envio em lote recebem em cópia oculta (CCO), quando esse for o comportamento configurado.

Pasta do aluno e anexos

  • Cada aluno tem uma pasta única por Nº USP no Google Drive — compartilhada conceitualmente com outros sistemas que usam o mesmo cadastro central de alunos;
  • "Abrir/criar pasta no Drive" abre a pasta se ela já existir, ou cria uma nova se ainda não existir. O aluno precisa ter cadastro na planilha central; sem cadastro, nada é criado e o aviso pede o cadastro pelo Gerenciador de Pessoas;
  • Em Anexos: lista de arquivos já existentes, opção de excluir um anexo, "+ Adicionar arquivo" e "Salvar Anexos";
  • O tipo de cada arquivo vem de uma lista de tipos já configurada no sistema.

Devolver para...

Esta é uma ação potencialmente disruptiva para o andamento do processo — precisa ser usada com clareza sobre o que ela invalida.

Exemplo: um aluno está na etapa Emissão de Diploma. Dependendo de para onde ele é devolvido:

AçãoO que fica invalidado (precisa ser reconfirmado)
Devolver para Dados PessoaisDados Pessoais + Histórico Escolar + Colação de Grau
Devolver para Histórico EscolarHistórico Escolar + Colação de Grau
Devolver para Colação de GrauColação de Grau

Cada etapa disponível para edição direta no só mostra as opções de "Devolver para..." que fazem sentido a partir da etapa atual daquele aluno.

Devolver não apaga anexos, não apaga o histórico de análises já registradas, não apaga a pasta do aluno e não apaga PDFs já gerados. A ação apenas limpa as marcações de confirmação daquelas etapas, fazendo o sistema recalcular a etapa atual do aluno para trás — o trabalho já feito continua guardado e acessível.

Exclusão de aluno

Esta ação não pode ser desfeita. Ela remove o registro do aluno nesta colação.
  • A pasta do aluno no Google Drive e os arquivos dela ficam guardados: a pasta é organizada por Nº USP e serve também a outras colações da mesma pessoa e a outros sistemas;
  • O cadastro do aluno na planilha central também não muda.

Confira sempre o Nº USP do aluno antes de confirmar a exclusão.

Regras curriculares

  • Os requisitos avaliados pela análise automática não estão fixos dentro do sistema — eles vêm de uma planilha própria de Regras Curriculares;
  • Existem conjuntos de regras (rulesets) diferentes para cada currículo/habilitação;
  • O currículo do aluno é identificado a partir do próprio histórico escolar dele;
  • Uma revisão feita hoje nas Regras Curriculares não altera retroativamente análises que já foram registradas antes dessa revisão.

As Regras Curriculares são administradas no painel específico de Configuração de Regras Curriculares.

Se o ruleset de um currículo/habilitação ainda não existir, a análise tende a retornar CONFERIR até que a regra seja cadastrada — ver .

Por que o sistema às vezes recusa uma ação?

Algumas recusas não são erro — são o sistema se protegendo contra situações arriscadas. Em linguagem simples:

  • Lista de acesso: a cada ação o servidor confere se a sua conta está na lista e se o seu perfil permite aquilo. Esconder ou mostrar um botão é só conveniência; quem decide é o servidor.
  • Registro e versão: cada aluno tem um identificador interno e um número de versão que aumenta a cada salvamento. Se alguém mais salvou uma alteração nesse meio-tempo, o sistema avisa em vez de sobrescrever silenciosamente.
  • Travas (locks): em operações sensíveis, o sistema evita que duas ações conflitantes aconteçam ao mesmo tempo sobre o mesmo aluno.
  • Validação da etapa no servidor: mesmo que a tela pareça permitir uma ação, o servidor confere de novo se aquilo realmente é permitido para a etapa atual — a tela nunca é a única linha de defesa.
  • Validação de pasta: o sistema só age sobre pastas que ele reconhece como gerenciadas por ele.
  • Substituição segura de arquivos: ao atualizar um documento, o sistema só remove o antigo depois de confirmar que o novo foi gerado com sucesso.
  • Fail-closed: na dúvida, o sistema prefere recusar a ação a arriscar um resultado incorreto.
  • Auditoria de análises: toda análise de histórico escolar fica registrada de forma permanente (nunca é editada ou apagada), o que ajuda a entender o que foi avaliado e quando.

Problemas comuns

Orientação prática para uma situação concreta. Para dúvidas de conceito, veja o .

"Apareceu o aviso de pedidos do formulário com pendência."
O que significa
Os pedidos enviados pelo Formulário de Pedido de Colação de Grau entram na lista sozinhos. O aviso mostra os que não puderam entrar (por exemplo, aluno sem cadastro na planilha central ou outro registro do mesmo Nº USP na mesma colação) e as correções enviadas pelo aluno depois que a conferência dos dados pessoais começou.
O que fazer
Leia o motivo de cada linha e resolva a causa (cadastro pelo Gerenciador de Pessoas, registro repetido na lista). O pedido entra sozinho na próxima vez que alguém da administração abrir a página. Uma correção retida não muda nada no registro: confira com o aluno e altere o que for preciso pela própria tela.
"Abrir/criar pasta diz que o Nº USP não tem cadastro."
O que significa
A pasta do aluno é ligada ao cadastro da planilha central. Este gerenciador não cria mais esse cadastro.
O que fazer
Cadastre o aluno pelo Gerenciador de Pessoas e tente de novo.
"O botão que eu esperava não aparece."
O que significa
Alguns botões só existem em determinada aba/etapa do aluno.
O que fazer
Confira em qual aba/etapa o aluno está e veja o Guia Rápido daquela etapa.
"O aluno não avança."
O que significa
Falta algum requisito, habilitação ou status pendente de confirmação.
O que fazer
Reveja a tabela de Habilitações e confirme se todas as marcações necessárias daquela etapa foram feitas.
"Histórico não encontrado."
O que significa
O analisador não localizou, na pasta do aluno, um Histórico Escolar Completo com nome/tipo reconhecível.
O que fazer
Confira se o arquivo certo (Histórico Escolar Completo USP) está anexado, com nome e tipo corretos — veja Pasta do Aluno.
"Foram encontrados vários históricos."
O que significa
Há mais de um arquivo candidato, e o sistema nunca escolhe por conta própria.
O que fazer
Remova ou renomeie o(s) arquivo(s) duplicado(s) até restar apenas um candidato válido.
"A análise retornou CONFERIR."
O que significa
O sistema não teve segurança suficiente para concluir sozinho.
O que fazer
Leia o motivo indicado e decida manualmente. Nunca marque como cumprido automaticamente só por causa do CONFERIR.
"PDF escaneado não foi lido."
O que significa
O leitor só reconhece texto real dentro do arquivo; uma imagem escaneada sem texto não é interpretável.
O que fazer
Use o histórico oficial em formato com texto real, não uma foto ou digitalização de imagem.
"Ver Última Análise diz que não existe análise."
O que significa
Ainda não há nenhuma sessão de análise persistida e válida para esse aluno.
O que fazer
Execute "Analisar Histórico Escolar (automático)" para gerar e registrar uma análise.
"Relatório individual não foi gerado."
O que significa
A geração do PDF depende de uma análise persistida (a sessão de análise já registrada para aquele aluno). A análise é a fonte canônica do resultado — o PDF é apenas um artefato derivado dela.
O que fazer
Verifique a mensagem exibida e tente gerar o relatório novamente. Se a análise estiver registrada, o resultado continua válido e consultável mesmo que a geração do PDF tenha falhado. Se a análise não tiver sido registrada, será necessário executar uma nova análise antes de gerar o relatório.
"Relatório consolidado não abriu."
O que significa
O relatório consolidado abre em uma nova aba do navegador.
O que fazer
Verifique se o navegador bloqueou a abertura (bloqueio de pop-up) e libere para este site.
"Já existe relatório deste aluno."
O que significa
O aluno já possui ao menos uma versão de relatório individual salva.
O que fazer
Escolha entre substituir a última versão ou criar uma nova versão — veja Relatórios.
"O sistema disse que o registro foi alterado por outra sessão."
O que significa
Outra pessoa salvou uma alteração nesse aluno depois que você abriu a tela.
O que fazer
Feche e reabra (ou recarregue) o Modal do Aluno, reveja os dados atuais e só então salve novamente.
"O e-mail já foi enviado."
O que significa
O sistema evita reenvios acidentais registrando que aquele e-mail já saiu.

Glossário

ANÁLISE DE HISTÓRICO
Processo (automático ou consulta manual) de conferir se um aluno cumpre os requisitos curriculares de uma habilitação, a partir do Histórico Escolar Completo.
APTO
Resultado que indica que todos os requisitos avaliados para aquela habilitação foram cumpridos.
CONFERIR
Resultado que indica que o sistema não teve segurança suficiente para concluir sozinho e pede conferência humana. Nunca é sinônimo de reprovação.
COLAÇÃO
A colação de grau; também o nome dado ao lote de trabalho (por exemplo, 20261) que reúne os alunos formandos de um mesmo período.
ETAPA
Uma das 4 fases do fluxo do aluno: Dados Pessoais, Histórico Escolar, Colação de Grau, Emissão de Diploma. É calculada pelo sistema, não escolhida livremente.
HABILITAÇÃO
Uma das formações possíveis (Formação de Psicólogo(a), Bacharelado, Licenciatura); um aluno pode ter mais de uma.
HISTÓRICO ESCOLAR COMPLETO
O documento oficial usado pela análise automática, distinto do Histórico Escolar Final. Precisa ter texto real (não escaneado).
MOTOR DE REGRAS
A parte do sistema que compara os dados extraídos do histórico com as Regras Curriculares e decide entre Apto, Não Apto e Conferir.
Nº USP
Número USP; identifica o aluno e a pasta dele no Drive.
PARSER
A parte do sistema que lê o PDF do histórico escolar no navegador e extrai os dados relevantes, antes da avaliação.
REGISTRO ID
Identificador interno de cada aluno cadastrado, usado pelo sistema para saber exatamente qual registro está sendo salvo.
RELATÓRIO CONSOLIDADO
Resumo administrativo de uma análise em lote, cobrindo vários alunos; não é salvo automaticamente.
RELATÓRIO INDIVIDUAL
Relatório detalhado de um único aluno/sessão de análise; salvo automaticamente na pasta do aluno, com versionamento.
REVISÃO DO RULESET
Uma atualização feita nas Regras Curriculares; não altera retroativamente análises já registradas antes da revisão.
RULESET
Conjunto de regras curriculares aplicável a um currículo/habilitação específico.
SESSÃO DE ANÁLISE
O registro de uma execução da análise automática, gravado de forma permanente na auditoria.
VERSÃO DO REGISTRO
Contador interno que aumenta a cada salvamento de um aluno; usado para perceber quando duas pessoas tentam salvar o mesmo registro ao mesmo tempo.
WEB APP
O aplicativo publicado (endereço /exec) usado no navegador; precisa ser atualizado/implantado de novo após mudanças no código.

Detalhes técnicos — para manutenção

Seção destinada a quem for manter ou evoluir o sistema no futuro — não é necessária para o uso diário.

O sistema é um Web App em Google Apps Script. O HTML é servido a partir de um arquivo principal que inclui outros arquivos HTML/CSS/JS por meio de uma função utilitária genérica de inclusão — é assim, por exemplo, que este próprio módulo de ajuda é carregado. A comunicação entre a tela (frontend) e o servidor (backend) acontece por chamadas assíncronas do tipo cliente-servidor próprias do Apps Script — nunca por requisições HTTP manuais.

Os dados dos alunos ficam em uma planilha própria do sistema de Diplomas, com uma aba auxiliar de configuração (tipos de arquivo, parâmetros gerais). Existe também um cadastro central de alunos, compartilhado conceitualmente com outros sistemas, que é a referência de qual pasta do Drive pertence a cada Nº USP. As Regras Curriculares vivem em uma planilha própria, separada, mantida por quem administra o currículo.

A leitura do PDF (parser) acontece inteiramente no navegador, nunca no servidor. Os dados extraídos são então avaliados no servidor por um motor de regras, que consulta o ruleset vigente para o currículo identificado. Cada execução gera uma sessão de análise, registrada de forma permanente (somente inserção, nunca edição ou exclusão) numa tabela de auditoria dedicada. Um hash do arquivo analisado é guardado como referência de integridade, sem expor o conteúdo do arquivo em si.

Sessões de análise são assinadas no servidor para impedir que uma tela alterada manualmente engane o sistema sobre qual foi o resultado real. O sistema segue o princípio de "fail-closed": diante de qualquer inconsistência, ele recusa a ação em vez de seguir em frente.

As garantias efetivas de registro e integridade, hoje, são estas — não existe um log geral e único de "toda ação do sistema":

  • análises de histórico escolar têm auditoria permanente, somente inserção (nunca edição ou exclusão);
  • cada registro de aluno tem identidade e número de versão, usados para controle de concorrência;
  • o envio de e-mails fica marcado, para evitar reenvio não intencional;
  • operações sensíveis contam com validações e travas (locks) apropriadas;
  • mudanças nas Regras Curriculares têm auditoria própria, no sistema responsável por elas.

Certificado, Ofício de Encaminhamento e Lista de Formandos/Convocação usam modelos (templates) do Google Docs, com marcadores de texto substituídos pelos dados do aluno, e então exportados para PDF. Os identificadores desses modelos não são expostos nesta ajuda.

Os relatórios de conferência de histórico escolar (individual e consolidado) são diferentes: não usam modelo fixo. Eles são construídos programaticamente (via DocumentApp), montando o documento inteiramente em código a partir do resultado da análise, e então exportados para PDF.

Qualquer alteração no código-fonte só passa a valer para quem usa o sistema depois que a implantação do Web App (/exec) é atualizada/publicada de novo — salvar o arquivo no editor não é suficiente.

Esta Central de Ajuda é conteúdo estático versionado junto do código (arquivos DiplomasAjuda.html, DiplomasAjudaEstilos.html e DiplomasAjudaUI.html). Regra de manutenção: sempre que uma funcionalidade relevante do sistema mudar, esta ajuda deve ser revisada e atualizada junto — ela não se atualiza sozinha.
